## Decisions

- Book Theme owns body font family/weight, `p`/`li`/`blockquote` family and weight, quote/epigraph type, and all heading roles — real `h1`–`h6` as well as detected pseudo-headings.
- KOReader owns base font size, line spacing, margins, contrast/gamma, hyphenation and UI chrome.
- The theme is authoritative for body type but writes the body face through to KOReader's font setting so the Aa menu agrees. KOReader Font Weight must be 0; the theme owns weight.
- Body size normalisation is out of v1; forcing `1rem` on every `p` would enlarge footnotes and small print.
- No EPUB rewriting. The plugin changes presentation only, preserving sidecars, progress, highlights and bookmarks.
- Per-book CSS cache must include a theme hash, so changing a theme font invalidates that book's cached CSS on the next open.
- The auto-compaction buffer is global at 80% of the model window with a 40K retained tail; subagents are enabled globally.

## Heading scale research (2026-11-23)

Owner feedback after trying Ysabeau: the chapter number looks bold, the minor heading is still too big, and the sizing needs research before another styling change. The durable note is `docs/heading-scale-research.md`.

- **Two regimes**: trade-book practice allows part/chapter titles at roughly 1.5–3.0x body, but treats in-chapter section heads as a 1.05–1.20x step and minor/C-heads as body size or one point smaller, distinguished by weight, case, style and space. The current 1.25 rem section and 1.05 rem uppercase minor apply the display scale to in-text levels.
- **Minor optical size**: 1.05 rem is only 5% above body in ems, but Ysabeau's cap height is 0.658 em against a 0.414 em x-height (ratio 1.59), so uppercase, bold and 0.05 em tracking make the line read much larger than 5%. Recommended 1.00 rem sentence-case bold, or 0.95 rem if uppercase is kept.
- **Chapter number**: 1.05 rem against the 1.50 rem chapter title is 0.70x, which is the right secondary relationship; the defect is the inherited `font-weight: bold`. Both number paths need `font-weight: normal`; the size stays.
- **Proposed ladder**: part 1.75 and chapter 1.50 unchanged; section 1.15; minor 1.00 (or 0.95 uppercase); number 1.05 regular. No plugin, generator or device change was made in this research round.

Revert to Noto Sans there if the UI face should go back. Book Theme itself still has exactly two choices (body and heading) and does not touch the UI font.
- The heading scale is now the researched recommendation and the owner's decision; the minor style question is closed (1.00 rem sentence case, no tracking).
- The chapter-number marker rule trusts the heading shape, not the publisher's class: it fires on any 1-3 digit first child with no whitespace and no `page`/`note`/`ref`/`bullet`/`marker`/`toc`/`index` class token. Corpus-wide that is 2 of 49 books and 0 paragraph false positives. Presentation is a fixed smaller block line above the title in regular weight; every book, including one that intends the number inline, is normalised to that form. That is deliberate, not a bug to chase.
- The standalone-number pair rule needs a class or id on both headings; bare `<h2>8</h2><h2>Title</h2>` is skipped because a tag selector would restyle every heading of that level. Corpus count is 5 books, so this is a small, deliberate gap.
- The follower rule only looks after the first heading of a document and after a number-pair title. A chapter title that is a detected pseudo-heading (not a real `h1`/`h2`) is not yet covered; none of the corpus complaints came from such a book, but it is the next place a publisher pull-up could reappear.
- Known cosmetic false positive: title-page furniture rules (`p.fm-title`, `p.title`, `p.subtitle` in *Relationality*) make a title page look like headings. They never touch body text; tightening them is optional.
- `edefee52` ToC recall is accepted as a miss: its 223 fragments point at empty inline `<a id>` anchors inside `p.calibre1`, so CSS cannot select their parent and crengine has no `:has()`.
- Optional later: body-size normalisation, per-book overrides, EPUB exporter (owner approval required).
